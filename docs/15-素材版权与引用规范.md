# 素材版权与引用规范

> 一句话：**文字可以自己写，图不能随便用。**
> 本站的性质是「评论与研究」，这在法律上属于「引用」或「合理使用」的范畴，但**不是免死金牌**。以下规范的目标不是「合法地随便用图」，而是**把风险降到可以接受，并且在被要求时能立刻撤下**。

> ⚠️ 本文是实务建议，不是法律意见。涉及商业化、出版、批量使用时，请咨询律师。

---

## 1. 风险分级

| 级别 | 素材类型 | 风险 | 策略 |
|---|---|---|---|
| 🟢 低 | 官方新闻稿图、官网 Key Visual、官方发布的角色设定图 | 低（官方本就用于宣传） | 可用，必须标出处 |
| 🟡 中 | 自行截取的单帧画面（低分辨率、单张） | 中（依赖「引用」抗辩） | 可用，但每部作品 ≤3 张，且必须有实质评论文字 |
| 🟠 较高 | 连续多帧、分镜表、原画集/设定集扫描页 | 高 | **禁止** |
| 🔴 高 | 整页漫画、整话截图、扫描的盗版资源 | 很高 | **禁止** |
| 🔴 高 | 同人二次创作、AI 生成的「仿作」 | 高（且涉及原作者人格权） | **禁止** |

## 2. 法律框架（够用版）

### 2.1 日本：著作権法第 32 条「引用」

日本法下，引用需要满足四个要件（判例累积形成）：

1. **明瞭区分**：引用的部分与自己的论述必须能清楚区分（图注、引用框、边框）。
2. **主従関係**：引用必须是**从属**的，自己的论述是主体。→ **这是本站最大的风险点**：如果一页里图占 80%、文字只有两行，很可能不满足「主从」。
3. **引用の必要性**：为了评论，必须展示该图。
4. **出典明示**：必须标明出处（作品名、权利者、来源）。

> 另外，2018 年新增的第 30 条之 4 允许「情報解析」使用，但**不包括「享受作品本身」的展示**。也就是说，「我做研究所以能放图」这个理由并不成立。

### 2.2 中国：著作权法第 24 条「合理使用」

「为介绍、评论某一作品或者说明某一问题，在作品中适当引用他人已经发表的作品」——同样要求**适当**（数量、比例）与**指明作者、出处**。

### 2.3 美国：Fair Use 四要素

使用目的（转换性）、作品性质、使用比例、市场影响。若站点托管在美国 CDN，理论上也可能被主张。**转换性越强（分析、注释、对比）越有利**。

### 2.4 平台层面

Cloudflare / GitHub Pages 等托管方会响应 DMCA 与日本权利方的删除请求。**下架流程必须提前写好**（见 §6）。

## 3. 硬性规范（写进内容生产流程）

| # | 规范 | 检查方式 |
|---|---|---|
| 1 | 每部作品**最多 3 张**图 | 数据校验（`images.length ≤ 3`） |
| 2 | 单张 ≤1600px 长边、≤200KB、质量 78 | 构建脚本检查 |
| 3 | **必须**有 `credit` 字段（作品名 + 权利者 + 来源） | 构建失败 |
| 4 | 图片下方必须有**实质评论文字**（≥150 字） | 人工审阅 |
| 5 | 禁止连续帧、分镜表、整页漫画、设定集扫描 | 人工审阅 |
| 6 | 禁止加滤镜、调色、加暗角 | 设计规范已禁止 |
| 7 | 禁止裁掉画面中的签名/水印 | 人工审阅 |
| 8 | 不提供原图下载；`<img>` 不带 `download` | 代码审阅 |
| 9 | 每页底部有「引用目的」声明 | 模板强制 |
| 10 | 权利方要求下架时 48 小时内处理 | 流程 |

## 4. 出处格式

### 4.1 图注（显示在图片下方，11px）

```
《冰菓》© 米澤穂信・角川書店／「氷菓」製作委員会｜京都アニメーション｜来源：公式サイト
```

**结构**：`《作品名》© 权利者｜制作公司｜来源`

### 4.2 数据字段

```json
{
  "src": "/images/works/2012-hyouka/hero.avif",
  "alt": "冰菓 主角正面特写",
  "credit": "© 米澤穂信・角川書店／「氷菓」製作委員会｜京都アニメーション",
  "source": "https://kotenbu.com/",
  "ratio": "16:9"
}
```

### 4.3 引用目的声明（页面底部模板）

> **关于本页图片**：本页所用图像仅用于对人物画法的评论与研究，图片版权归各权利者所有。图像以低分辨率、单张形式引用，不提供下载；如权利方认为使用不当，请联系 `[邮箱]`，我们将在 48 小时内移除。

## 5. 低风险的替代方案（优先采用）

真正降低风险的办法不是「写免责声明」，而是**少用别人的图**。

| 方案 | 做法 | 适用 |
|---|---|---|
| **自绘示意图** | 用 SVG 画出「鼻子的三种画法」「眼睛高光的两种结构」 | 九维度分析、时期对比 |
| **线条提取图** | 对截图做边缘提取，只保留线条（不呈现原作画面） | 讲「线」的维度 |
| **色卡** | 从作品中提取 5–8 个主色做成色块 | 讲「色」的维度 |
| **比例图** | 用几何图形标出头身比、眼距比 | 讲「比例」的维度 |
| **官方宣传图** | 优先用官方新闻稿、官网 Key Visual | Hero 图 |
| **公有领域** | 1955 年以前的作品（日本保护期 70 年） | 前史说明 |

> **建议比例**：每篇赏析里，**至少 1 张自绘示意图**，至多 2 张截图。这样既降低风险，也更符合「研究」的定位——示意图比截图更能说明「画法」。

## 6. 下架与更正流程

```
1. 收到请求（邮件 / 平台通知 / SNS）
        ↓ 24h 内
2. 确认请求方身份与具体 URL
        ↓ 48h 内
3. 移除图片 → 替换为自绘示意图或纯文字
        ↓
4. 在 /method 的「更正记录」中登记（日期、内容、原因）
        ↓
5. 回复请求方，说明处理结果
```

**需要的准备**：

- 一个公开的联系邮箱（`contact@[域名]`）。
- `assets-register.csv`：记录每张图的 `id / src / credit / source / 添加日期 / 状态`。
- 所有图片都放在 `src/assets/` 下并用 `id` 命名，**便于一次性批量删除**。

## 8. 不可做的事（红线）

1. ❌ 整页漫画、整话截图、扫描的设定集/原画集。
2. ❌ 以「图集」「壁纸」「资源」为卖点的页面。
3. ❌ 提供打包下载、网盘链接。
4. ❌ 用 AI 生成「某画师风格」的图来替代原作。
5. ❌ 把截图裁成表情包或做成周边。
6. ❌ 商业化（广告、付费墙）而不重新评估版权。
7. ❌ 用「仅供学习交流」当作免责声明——它没有法律效力。
