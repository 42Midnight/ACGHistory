# 实施路线图与验收标准

> 本文件不实现网站，只定义**下一步怎么走、走到哪里算完成**。
> 前期准备（本仓库当前状态）已完成；以下从 M1 开始。

---

## 1. 两条并行线

```
内容线：M0 数据定稿 → M1 长文与赏析 → M6 素材与示意图 → M7 上线前审校
工程线：M1 设计原型 → M2 脚手架 → M3 时间轴 → M4 时期页 → M5 详情页 → M7 优化发布
```

两条线在 **M2** 汇合（工程开始消费内容数据），在 **M7** 再次汇合（审校与发布）。

---

## 2. 阶段与验收

### M0｜数据定稿（前置条件，已完成 80%）

| 项 | 产出 | 验收 |
|---|---|---|
| 124 条数据 | `data/entries.json` | `build_docs.py --check` 通过 |
| 六期定义 | `data/periods.json` | 区间无重叠、无缺口 |
| 待核清单 | `17-待核对事实清单.md` | 全部 `medium` 条目都有待核项 |

**剩余工作**：把 `17` 里的待核项逐条查证，把 `medium` 升到 `high` 或降级说明。预估 **3–5 人日**。

---

### M1｜设计与原型

| 项 | 产出 | 验收 |
|---|---|---|
| 设计 token | `tokens.css` 初稿 | 与 `13` 一致；六期色可用于色带与图表 |
| 高保真首页 | Figma 或 HTML 静态稿 | 通过「三秒能看懂这是什么站」测试 |
| 时间轴原型（可点） | 静态 HTML + JS，不接数据 | 悬停/固定/键盘可用；移动端可用 |
| 详情页原型 | 静态稿 | 标注热点可点开 |

**验收标准**：让 3 个没看过需求的人操作原型，能不看说明完成「找到一个 2007 年的作品并打开它」。预估 **5–8 人日**。

---

### M2｜脚手架

| 项 | 产出 | 验收 |
|---|---|---|
| Astro 项目 | `site/` | `pnpm dev` 可跑，`pnpm build` 通过 |
| 数据接入 | Zod schema + 构建期校验 | 故意改错一个字段，构建失败并给出可读报错 |
| 设计 token | Tailwind 主题接入 | 颜色/字号/间距全部来自 token |
| 部署 | Cloudflare Pages 预览 | 每次 PR 有预览链接 |
| CI | 校验 + 构建 + Lighthouse | 红灯不可合并 |

**验收标准**：`main` 分支一次提交后，预览站自动更新；构建时间 ≤2 分钟。预估 **3–4 人日**。

### M3｜时间轴页

| 项 | 验收 |
|---|---|
| 31 个年份刻度 | 1996–2026 全部可选；整十年刻度加长 |
| 悬停预览 | 120ms 延迟生效；4 张卡 40ms 依次入场 |
| 点击固定 | 鼠标离开不改变内容；`Esc` 取消 |
| 键盘 | `←/→/Home/End`；`Tab` 进入卡片；焦点可见 |
| 触屏 | 点年份展开；卡片纵向排列 |

| 性能 | 切换年份不触发重排；首屏 JS ≤120KB |
| 降级 | 无 JS 时显示「年份列表 + 卡片」静态版 |

预估 **8–12 人日**（这是全站最难的一页）。

## 4. 明确不做的事（YAGNI）

| 不做 | 理由 | 什么时候再做 |
|---|---|---|
| 站内搜索 | 124 条数据，按年/期找更快 | 超过 300 条时 |
| 中英双语 | 没有英文读者需求 | 有海外流量后 |
| 用户账号/收藏 | 静态站，无后端 | 不做 |
| 评论/弹幕 | 审核成本高 | 不做 |
| CMS 后台 | `git` 即 CMS | 非技术合作者 >2 人时 |
| 全站暗色模式 | 只有详情页需要暗底 | 有明确需求时 |
| AI 生成配图 | 版权与伦理风险 | 不做 |
| 自动播放的时间轴动画 | 干扰阅读 | 不做 |
| 3D/WebGL 特效 | 与「档案」气质不符 | 不做 |

## 5. 验收标准（Definition of Done）

一个页面「做完」需要同时满足：

### 5.1 内容

- [ ] 数据字段完整（`14` 的 Schema 全部通过）
- [ ] `why` 含可观察的画法，不是评价
- [ ] 至少 1 个前/后对比对象
- [ ] 主创与年份可查证，或已在 `17` 登记
- [ ] 图片有 `credit`，页脚有引用声明

### 5.2 设计

- [ ] 只用 token 里的颜色/字号/间距
- [ ] 六期主色只用于图形，不做正文
- [ ] 图片不加滤镜、不裁签名
- [ ] 1440 / 1024 / 768 / 375 四个宽度都不破版

### 5.3 交互与无障碍

- [ ] 键盘可完成全部操作
- [ ] 焦点可见（2px 环）
- [ ] `prefers-reduced-motion` 下无动效
- [ ] 触屏目标 ≥44×44px
- [ ] 无 JS 时内容仍可读

### 5.4 工程

- [ ] `pnpm build` 通过，无 TypeScript 错误
- [ ] CI 绿灯（校验 + 构建 + Lighthouse）
- [ ] 首屏 JS ≤120KB（gzip）
- [ ] 页面无 console 报错

## 6. 风险登记册

| # | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| 1 | 图片拿不到或版权所有方拒绝 | 高 | 高 | 提前准备自绘示意图；每篇至少 1 张不依赖截图 |
| 2 | 主创/年份记错 | 中 | 中 | `17` 清单逐条核对；`confidence` 分级 |
| 3 | 时间轴交互在移动端体验差 | 中 | 高 | M1 先做移动端原型；卡片改纵向 |
| 4 | 中文字体体积失控 | 中 | 中 | 标题字体子集化；正文用系统字体 |
| 5 | 内容量不足（写不出 124 篇） | 中 | 高 | 先写 24 篇（每期 4 篇）上线，其余逐步补 |
| 6 | 设计与内容冲突（图太少/字太多） | 中 | 中 | M1 用真实内容做原型，不用 Lorem Ipsum |
| 7 | 审美主观，反复改稿 | 高 | 中 | 以 `13` 的 token 为唯一依据，改稿只改 token |
| 8 | 版权投诉 | 低 | 高 | `15` 的红线与下架流程 |
| 9 | AI 生成内容争议 | 低 | 中 | 明示「不生成仿作」 |
