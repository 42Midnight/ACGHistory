# 技术栈选型

> 结论：**Astro 5 + TypeScript + Tailwind CSS 4 + React 岛屿 + Motion + 静态输出**。
> 备选：Next.js 15（若后期要做账号／CMS／服务端）；纯 Vite SPA（不推荐）；Eleventy + 原生 JS（极简方案）。
> 本文只做决策，不含实现。

---

## 1. 先把需求翻译成技术约束

| 需求 | 技术含义 |
|---|---|
| 时间轴页：悬停年份 → 并行展示 4 张卡；点击进详情 | 一个**局部交互岛屿**，需要状态、动画、键盘与触屏支持；不需要整页 SPA |
| 时期页：长文 + 图表 + 图组 | **内容驱动**，需要 Markdown/MDX 与类型化 frontmatter |
| 124 个详情页 | **构建期静态生成**，每页独立 URL（可分享、可被搜索） |
| 图片多、体积大 | 构建期图片优化（AVIF/WebP、多尺寸、懒加载、模糊占位） |
| 中文长文排版 | 对 CSS 与字体子集有控制权 |
| 一个人维护 | 内容与代码同仓库，`git` 即 CMS；构建要快、报错要清楚 |
| 部署便宜 | 纯静态，任意静态托管 |
| 未来可能扩展 | 预留「换成 Next」的成本要低（组件与数据模型独立于框架） |

**关键判断**：这不是一个「应用」，是一个**带局部交互的内容站点**。凡是把整站做成 SPA 的方案，都会在首屏、SEO 与内容维护上付出不必要的代价。

---

## 2. 四个候选方案

| 方案 | 一句话 | 适合谁 |
|---|---|---|
| **A. Astro 5 + React 岛屿** | 默认零 JS，交互处才注水 | 内容为主、交互局部化 |
| **B. Next.js 15（App Router，静态导出）** | 全功能 React 框架 | 预期会长成应用 |
| **C. Vite + React SPA** | 纯前端应用 | 交互极重、无 SEO 需求 |
| **D. Eleventy + 原生 JS** | 最轻的静态站 | 不想碰框架 |

## 3. 加权评分

权重按「这个项目最怕什么」定：最怕内容难维护，其次怕首屏慢、交互做不出来。

| 维度 | 权重 | A Astro | B Next | C SPA | D 11ty |
|---|---|---|---|---|---|
| 内容维护（Markdown/类型/热更新） | 25% | 5 | 4 | 2 | 5 |
| 性能（首屏、JS 体积） | 20% | 5 | 4 | 2 | 5 |
| 交互实现（时间轴、动画） | 20% | 4 | 5 | 5 | 2 |
| 部署成本与稳定性 | 15% | 5 | 4 | 4 | 5 |
| 后期扩展（CMS／账号／i18n） | 10% | 3 | 5 | 4 | 3 |
| 学习与调试成本 | 10% | 4 | 3 | 5 | 3 |
| **加权总分** | 100% | **450** | 420 | 340 | 400 |

**A 胜出的原因**不是「它更强」，而是「它的默认值刚好是这个项目需要的」：默认不发 JS、内容集合自带类型、图片优化在构建期完成。

## 4. 推荐栈（逐项说明为什么）

### 4.1 框架：Astro 5

- **内容集合（Content Collections）**：用 Zod 定义 frontmatter，构建期校验。124 条数据写错一个字段，`astro build` 直接失败——这对「一个人维护 124 条数据」是决定性的。
- **岛屿架构**：时间轴是一个 `client:visible` 的 React 岛屿，其余页面零 JS。
- **静态输出**：`output: 'static'`，产物是纯 HTML/CSS/JS，扔到任何 CDN 都能跑。
- **View Transitions**：`<ClientRouter />` 提供接近 SPA 的页面切换，用于「卡片 → 详情页」的连续感。

### 4.2 语言：TypeScript（strict）

数据模型、组件 props、Zod schema 共用一套类型。124 条数据的字段错误在编译期暴露。

### 4.3 样式：Tailwind CSS 4 + CSS 变量

- Tailwind 负责布局与原子样式；**设计 token 用 CSS 变量**（`--period-p1: #3A5A7A` 等），这样「按时期换主色」只需要切换一个变量。
- 不引入组件库（不需要 MUI/AntD 那套东西）；需要的基础组件自己写，约 10 个。

### 4.4 交互：React 19 岛屿 + Motion

- 只在一个地方用 React：**时间轴岛屿**（年份选择、卡片并行展开、键盘导航、URL 同步）。
- 动画用 `motion`（原 Framer Motion）：`AnimatePresence` 处理年份切换的进出场；`prefers-reduced-motion` 时降级为淡入。
- **不引入状态管理库**：一个 `useState` + `useReducer` 足够。

### 4.5 内容：MDX + JSON

- **长文**（六篇时期研究、方法说明）用 MDX：可以在正文里嵌图表组件。
- **结构化数据**（124 条）用 JSON：与 `docs/` 生成脚本共用同一份 `data/entries.json`，避免两处维护。
- 详情页的赏析正文：优先放在 `data/entries.json` 的 `analysis` 字段（短），超过 800 字再拆成 `src/content/works/{id}.mdx`。

### 4.6 图片：`astro:assets` + Sharp

- 构建期生成 AVIF/WebP，多尺寸（400/800/1600），自动 `srcset`。
- 用 `getImage()` 生成模糊占位（LQIP），避免布局跳动。
- 图片放 `src/assets/`（参与优化），不放 `public/`（原样输出）。

### 4.7 搜索（可选，第二期再做）

124 条数据在前端搜索不需要服务端：`Pagefind`（构建期生成索引）或 `Fuse.js`（运行时，约 12KB）。**第一版不做搜索**，用「时期 + 年份 + 类别」的筛选代替。

### 4.8 部署：Cloudflare Pages 或 GitHub Pages

- 纯静态，`pnpm build` 产物直接上传。
- 国内访问优先考虑 Cloudflare Pages + 自定义域名；GitHub Pages 在国内速度不稳定。
- **不需要 Vercel**（它的优势在 SSR/边缘函数，这个项目用不上）。

### 4.9 工具链

| 用途 | 选择 |
|---|---|
| 包管理 | pnpm |
| 代码规范 | Biome（格式化 + lint 一体，比 ESLint+Prettier 配置少） |
| 单元测试 | Vitest（测数据校验与工具函数） |
| 端到端 | Playwright（测时间轴的键盘、触屏、URL 同步） |
| 视觉回归（可选） | Playwright 截图对比 |
| 性能预算 | Lighthouse CI（LCP < 2.0s、CLS < 0.05） |
| 数据校验 | `scripts/build_docs.py --check`（已有），CI 里跑 |

## 5. 为什么不是另外三个

### 5.1 不用 Next.js 的理由（尽管它很强）

- **用不上 SSR**：没有账号、没有个性化、没有实时数据。Next 的核心优势在这个项目里是空转。
- **静态导出会削掉 `next/image` 的优化**：需要额外配置或改用第三方 loader，等于把 Astro 的默认能力重新实现一遍。
- **RSC 的心智负担**：一个人维护的项目，不需要「服务端组件 / 客户端组件」的边界判断。
- **但仍然保留退路**：组件与数据模型不依赖 Astro 特有 API，真要做成应用时可以迁移。

### 5.2 不用纯 Vite SPA 的理由

- 124 个详情页在 SPA 里是「一个路由」，首屏要等 JS、SEO 差、分享链接要靠路由参数。
- 文章类内容在 SPA 里没有天然的「构建期校验」。

### 5.3 不用 Eleventy + 原生 JS 的理由

- 它其实很合适（评分 400），但时间轴岛屿要手写状态管理与动画，代码量会超过 Astro + React 的组合。
- 若坚持「零框架」，选它是合理的——这是唯一一个「换掉 Astro 也不会出错」的备选。

## 7. 性能与质量预算

| 指标 | 目标 | 说明 |
|---|---|---|
| 首屏 JS（gzip） | ≤ 120 KB | 时间轴岛屿 + 路由 |
| LCP（4G，中端机） | ≤ 2.0 s | 首图用 AVIF + 预加载 |
| CLS | ≤ 0.05 | 所有图片有宽高比 |
| Lighthouse 性能 | ≥ 90 | 移动端 |
| 可访问性 | WCAG 2.2 AA | 键盘可达、对比度、焦点可见 |
| 单页图片总量 | ≤ 1.5 MB | 首屏 1 张，其余懒加载 |
| 构建时间 | ≤ 2 min | 124 页 + 图片优化 |

## 8. 版本与浏览器支持

- 目标浏览器：Chrome/Edge 最近 2 个大版本、Safari 16+、Firefox 最近 2 个版本。
- **不使用**：`View Transitions` 之外的实验性 CSS（`@scope`、`anchor-position` 可渐进增强）。
- Node 20 LTS 或以上；pnpm 9 或以上。
